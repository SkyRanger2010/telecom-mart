# telecom-mart

Дипломный проект магистратуры ВШЭ «Инженерия данных». Платформа для расчёта KPI телеком-оператора: от загрузки сырых данных до дашбордов.

Данные идут по слоям: `RAW → Validate → DDS (SCD2) → MART (Iceberg/Trino) → ClickHouse → Django`. Плюс болталка NL2SQL, чтобы спрашивать у платформы «сколько абонентов за месяц» человеческим языком.

## Как устроено

```
Источники (BSS/OSS/CRM)
    ↓ Airflow DAG'и
RAW — сырые данные как есть, в MinIO
    ↓ schema check + completeness/validity
DDS — доменные таблицы, SCD2 по заказам и клиентам
    ↓ агрегация в Iceberg (через Trino)
MART — витрины KPI
    ↓ репликация python-скриптом
ClickHouse — serving, ради скорости
    ↓
Django-дашборды + JSON API
    ↓
NL2SQL (LLM → SQL Guard → ClickHouse, только read-only)
```

- **Airflow** гоняет DAG'и: загрузка RAW, прогон по слоям, проверки качества, публикация в ClickHouse.
- **Trino + Iceberg** на MinIO — озеро. Iceberg взяли потому что ACID и time travel, без них в SCD2 была бы каша.
- **ClickHouse** для serving — к нему ходят дашборды и API. Trino для интерактива слишком медленный на наших объёмах.
- **Django** — пара страниц с графиками и честный REST API под капотом. Никаких фреймворков для дашбордов, только Chart.js.
- **NL2SQL** — Qwen через API, запрос прогоняется через SQL Guard (блокирует DDL/DML, лимитирует строки). Костыль, но для MVP сойдёт.

## Быстрый старт

```bash
cd deploy/compose
cp .env.example .env
# правим пароли и порты
docker compose up -d
```

Дашборды после загрузки MART и репликации в ClickHouse:

- Абонентская база: `http://localhost:8090/`
- Финансы (ARPU, выручка): `http://localhost:8090/financial/`

Порт — `DASHBOT_STUB_PORT` в `.env`.

## Какие KPI считаем

- **АБ0** — активные абоненты на дату среза
- **АБ30, АБ90** — то же за 30 и 90 дней
- **ARPU** — средняя выручка на абонента, с нормализацией по типу периода (месяц/год/разовый)
- **Выручка** — дневная, месячная, квартальная, годовая
- **Приток/отток** — новые подключения и отключения за период

Все метрики можно фильтровать по сегменту, виду услуги, тарифу, типу клиента (физлицо/юрлицо/ИП, РФ/нерезиденты/УКР). Методика расчёта и SQL — в `VKR_SCOPE_MVP.md`.

Это диплом магистратуры ВШЭ (ФКН, «Инженерия данных», 2026). Задача была — собрать работающий контур от сырых данных до дашбордов с воспроизводимым запуском. Не «production-grade», но архитектура честная: слои изолированы, DQ-гейты на месте, схема версионируется.
